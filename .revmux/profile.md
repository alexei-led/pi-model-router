# Project review profile

This TypeScript Pi extension routes turns across configured provider models. Review the current semantic/baseline contract, not the superseded keyword-floor design. Four tiers (micro, low, medium, high) describe configured model/effort choices, never tool permissions. Pi owns tool execution and per-request authentication. Provider/profile isolation is required; backend-login attestation, auth-storage inspection and fingerprints are explicitly out of scope.

A material finding must demonstrate a user-visible correctness, security, reliability, compatibility or operational defect. Prioritize invalid candidates or actual fallback targets, capability/effort mismatches, broken continuations, credential/config provenance, unapproved external transmission, cancellation/streaming failures and state/debug/UI leakage. Do not report style preferences, speculative frameworks or test gaps without a plausible defect.

## Revised routing contract

- No prompt words, language, punctuation, length or inferred phase determine a local tier. Do not request keyword safety floors, mechanical allowlists, regex intent routing or a hidden legacy mode. Deprecated rules and phaseBias load with a fixed value-free warning and have no effect.
- baselineTier optionally names a configured tier. Filter live availability/input/effort, then prefer that baseline and medium, high, low, micro. Partial profiles are valid for any text when capable. Pins select only their configured tier and fail actionably if ineligible; words never override them.
- Above the soft generation budget, unpinned requests skip advisors and prefer eligible medium-or-lower tiers; otherwise retain an eligible configured baseline with a fixed budget diagnostic. Advisor costs are excluded. This is not a hard billing cap.
- Validated same-turn tool continuations precede advisors; invalid continuations use a compatible local route without advice. Keep bounded interleaved records and task/tool identity, branch, profile, canonical provider/model, config/thinking and live capability checks. Preserve Google transcript compatibility, cancellation and no retry after visible content.
- One effective eligible plan bypasses advice; a single tier with distinct activity plans may ask activity-only. One user-selected Pi classifier requires user-level enablement and active-profile approval for its exact canonical reference. Use public modelRegistry.classify() and Pi-owned auth, never a direct Jev/provider transport. Only current prevalidated matrix cells may generate; ordered generation fallbacks are not extra advisor choices.
- Initial abstention, invalid advice or classifier failure means baseline, never an advisor cascade. Below confidenceThreshold, resolve the full tier distribution against probabilityThreshold; activity is independent and uncertain activity uses generic/baseline. One advisor.timeoutMs deadline (default 10 seconds) covers public Pi classification and retries. Valid continuations may start bounded nonblocking reviews; only the immediately following request may consume a fresh fenced result. Failed/stale reviews retain the eligible incumbent. Caller abort never permits generation.
- Default-owned OpenAI activities and exact homogeneous new-example generic ladders may use normalized runtime-only model-first mode preferences. Generic declarations are not rewritten; explicit activity/session cells win. activityPreset:off disables all automatic defaults, while activityRouting:off excludes activities only. Other/custom/mixed profiles keep legacy transforms. Validate exact-provider live metadata before selection; missing/zero prices do not establish cheaper cost routes. Ineligible preferences use eligible legacy transforms, never implicit generation retries. Logical-medium Sol remains medium over the soft budget; only true high-source tier promotions are barred. Cost/high repeated-failure recovery restores eligible balanced high cells with existing bounded native-owner/config/policy/branch fences.
- Advisor context is bounded, role-labelled recent user/assistant/tool text, prioritizing the latest user request with deterministic truncation. No system prompts, raw config/config credentials, thinking, tool-call arguments or binary blocks. Conversation text may itself contain private data: this is not a redaction service. No work-profile enablement or project-level opt-in. Semantic confidence is probabilistic, not an intent/security guarantee.
- Revalidate actual generation/fallback targets and preserve exact fallback alias metadata. Parse normalized canonical references directly, without a second alias lookup. Explicit provider fallbacks are intentional; do not demand a new provider proxy, account subsystem, model discovery or cost optimizer.
- Persist only allowlisted local metadata and fixed reasons/diagnostics. Map obsolete sources to legacy without losing unrelated pins/cost/settings. Never persist remote explanations, key/endpoint, request text or raw responses. Clear stale advisor diagnostics on continuation.

## Evidence gate

Review one fixed commit with complete sources, including imports, config/normalization, context, routing, advisor adapters, provider, state/UI/commands and corresponding tests. Read the current README and architecture contract. Prior reviews and follow-up plans are historical, not authority to restore deleted behavior. Return precise source references and reproducible contract violations; distinguish accepted limitations from defects. An incomplete-source or unfinished review cannot close the gate.
